# 酒店报价与时间规则

酒店搜索结果的 `price` 只保存为 `display_price`。无论10元还是618元，都不能证明是整间房每晚价格，因此 `price_per_night` 留空，费用合计不包含该展示价。程序不按价格高低猜测报价是否可信。

没有确认报价时，方案仍可用于比较交通，但状态为 `needs_confirmation`，CLI 退出码5，预算为未知，并列出需确认事项。没有任何酒店结果时也会保留可用交通并提示确认住宿，不会据此声称整座城市不能去。

只有用户在实际预订页面核实，或明确提供了可靠的整房报价，才能在请求中填写以下字段。智能体不得自行填入 `confirmed: true`。这项确认不代表程序已核实库存或已下单。

```json
{
  "hotel_quote": {
    "confirmed": true,
    "hotel_name": "用户已核实的酒店名称",
    "city": "杭州",
    "room_price_per_night": 300,
    "max_guests_per_room": 2,
    "check_in_date": "2026-10-20",
    "check_out_date": "2026-10-22",
    "source": "用户在预订页面确认的房型报价",
    "late_checkin_confirmed": false
  },
  "arrival_buffer_minutes": 60,
  "departure_buffer_minutes": 90
}
```

上面的300元只是格式示例，不是真实酒店价格。确认报价仅用于对应城市和相同入住/退房日期。日期、每房可住人数不匹配时会阻止使用。当前按每房最多2人校验；不能通过把3人塞进某间房、另一间空置来通过总床位检查。费用按总房价平均分摊给所有成员。

共同停留区间 = 最晚交通到达 + 到站后缓冲 → 最早返程出发 - 离站前缓冲。默认分别60和90分钟，用户可调整；这是计划估计，未核实具体机场/车站到酒店的路程，也不等于游玩时长。跨日到达还会提示确认夜间入住和房间保留；只有明确核实后才能设置 `late_checkin_confirmed: true`。

住宿未确认时，城市排序只能比较已知交通费用，补齐住宿可能改变排序。即使交通与住宿参考价齐全，餐饮、接驳、门票等仍未计入；不要把已知小计当整趟旅行总价。

到家硬截止还会在返程到站时间后加home_buffer_minutes（默认60分钟）。这是可配置的接驳估计，不是实际到家路线验证。


普通聊天可以直接补充酒店名/房型、城市、入住退房日期、每房每晚含税价、每房人数和来源，智能体整理后请用户确认，不让用户手写JSON。缺字段时继续标记未知。同日深夜（22点后或6点前）到达也提示夜间入住；到站时间不是到店时间，接驳和房间保留须核实。
